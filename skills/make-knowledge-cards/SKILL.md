# Make Knowledge Cards

## Overview

把一篇文章变成一组高密度的知识卡片：每张卡片只讲一个知识点，只使用原文中的信息，内容不足时如实少给，不为凑数而编造。

## 输入处理

- 接受两类输入：用户直接粘贴的文章正文；本地 Markdown（`.md`/`.markdown`）或纯文本（`.txt`）文件。
- 收到文件路径时，先读取文件内容再处理；若文件不存在或读取失败，说明情况并请用户重新提供。
- 不抓取网页、不解析 PDF、不生成 Anki 包、不操作图形界面。遇到这类请求，明确说明暂不支持，并请用户粘贴正文或提供 `.md`/`.txt` 文件。
- 不追问用户文章主题或偏好，直接基于给定内容工作。

## 工作流程

### 1. 通读原文

完整读取输入内容，识别文章的主旨、论证结构和结论。不要只扫标题或开头就下结论。

### 2. 筛选真正重要的知识点

只收录满足以下条件的知识点：

- 是文章的核心概念、原理、机制、方法、结论或重要区分；
- 去掉它会明显损害对文章的理解；
- 原文对此有明确陈述或实质论证。

排除：背景铺垫、修辞、重复表述、无关轶事、只有情绪色彩没有信息量的句子。若某段只是引入话题、其实质信息已被其他卡片覆盖，不为它单独建卡。作者明确标注为"次要""补充"的内容，除非确实影响理解，否则不单独成卡。

### 3. 一卡一点，合并重复

- 一张卡片只讲一个知识点。若某段文字同时包含两个独立知识点，拆成两张卡；若两个知识点本质相同，合并为一张。
- 用"这张卡能否用一句核心知识概括且不需要补充第二个主张"作为检验标准。
- 删除重复内容：同一结论在不同段落反复出现时只保留一张卡，并吸收其中更精确的表述。
- 观点类文章尤其注意：总论点与分论点如果只是同一主张的修辞性重述，不拆成两张卡；只有核心主张不同才各自成卡。

### 4. 确定卡片数量

- 以 5~8 张为目标，但数量必须从内容中"长出来"，而不是先定数量再填满。
- 原文只有 3 个扎实的知识点时，就只输出 3 张，并在末尾用一句话说明"原文可提炼的独立知识点不足 5 个"。
- 知识点超过 8 个时，按重要性排序，保留最能代表文章主旨的 8 个，丢弃次要项。
- 绝不通过拆分同一知识点、复述或编造来凑数。

### 5. 撰写每张卡片

每张卡片严格包含四个字段：

- **标题**：简短、具体，直接点出该知识点，不使用"要点一"这类空泛标题。
- **核心知识**：一句话陈述该知识点，是卡片唯一的中心主张；若需要用"和""同时""以及"连接两个独立主张，应拆成两张卡。
- **简明解释**：用简洁的语言说明它是什么、为什么重要或如何成立；解释必须能追溯到原文。
- **例子或自测问题**：二选一，只写其中一个字段，标签随之写"例子"或"自测问题"。原文有具体例子时，优先照实引用原文的例子（可精简长度，但不要改造或杜撰细节）；原文没有例子时，出一个仅依据原文即可回答的自测问题。不要把答案写进问题里。

只使用原文中存在的信息。不补充背景知识，不引入原文未提及的数据、案例、人名、结论。解释中的推断必须是对原文表述的转述，不能是新的主张。

### 6. 逐项自检

输出前逐条核对：

- 每张卡片的"核心知识"能否在原文找到依据？
- 是否有卡片包含两个及以上知识点？
- 是否有两张卡片讲同一件事？
- 例子是否来自原文；自测问题的答案是否能从原文推出？
- 是否出现了原文没有的信息？
- 卡片数量是否由内容决定，而非为凑 5~8 张硬凑？

发现问题就回到第 3~5 步修正，再输出。

## 输出格式

使用 Markdown，按下面结构输出。不要输出分析过程、 checklist 或额外说明；唯一的例外是内容不足时的那句简短说明。

```markdown
## 1. 标题

- **核心知识**：一句话陈述。
- **简明解释**：两三句解释。
- **例子**（或 **自测问题**）：原文中的例子，或依据原文提出的自测问题；只保留一个。

## 2. 标题
...
```

格式示例（仅演示结构，不代表任何真实文章）：

```markdown
## 1. 复利效应依赖持续时间

- **核心知识**：复利的关键变量是持续时间，而非单期收益率。
- **简明解释**：原文指出，早期微小的差异会在长期反复相乘后放大。
- **自测问题**：根据原文，为什么起步时间比单年收益率更影响最终结果？
```

## 语言

- 卡片正文整体使用一种语言：默认与原文正文一致；用户明确要求某种输出语言时，按用户要求。
- 用户用英文下达指令但提供中文原文时，卡片正文用中文，不要混用语言。
- 保留原文中的专有名词和术语原名，必要时附原文表述。
